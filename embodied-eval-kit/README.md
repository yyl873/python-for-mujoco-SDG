# embodied-eval-kit

**Evaluation numbers that survive scrutiny.** Exact small-sample statistics, a
counterfactual pairing protocol for language-conditioned policies, clean-success gates,
and three-state receipts — in ~1,600 lines of dependency-free Python.

```
python -m pip install -e ".[test]"
python examples/demo_real_run.py     # real 76-rollout log, no downloads
python -m pytest tests -q            # 134 tests, ~6 s, standard library only
```

The motivating failure, from the project this kit was extracted from: a policy was
reported at **100% instruction-following accuracy**. It was also true that the policy put
the box on the instructed side in only **15 of 38 scenes**. Both statements came from the
same data. The first used "rollouts that landed in *some* box" as its denominator; the
second used paired counterfactual replays. Choosing the denominator is what decides
whether a robot demo is a result or a story.

| what | why it exists |
|---|---|
| `eeval.stats` | small samples lie: 40/40 is **91.2%** at the lower 95% bound, not 100% |
| `eeval.counterfactual` | one number cannot both measure skill and resist a degenerate policy |
| `eeval.judge` | "it lifted" rewards digging into the object and lifting the debris |
| `eeval.receipt` | a stage that prints `warn` must never roll up to `ok` |

## Try it in 30 seconds

```bash
python -m eeval report examples/data/language_pair_76rows.json \
  --tasks "Put the medicine box into the left wooden box.,Put the medicine box into the right wooden box." \
  --boxes "target_box,target_box_b"
```

```text
**Verdict: instruction followed** (pass)

| estimand | value | denominator |
|---|---|---|
| follow_acc | 100.0% | 40 rollouts that landed |
| follow_acc (ITT) | 52.6% | 76 rollouts |
| pairs both followed | 15 / 38 (39.5%) | complete pairs |
| Wilson 95% of follow_acc | 91.2% - 100.0% | - |
| p vs chance (0.50) | < 1e-6 | - |
| side bias p (landing counts {'target_box': 25, 'target_box_b': 15}) | 0.1539 | - |
```

Exit code `0` when the pre-registered verdict passes, `1` when the report is produced
but the verdict fails, `2` on bad input — so a shell or CI job can gate on it.

## Proof the arithmetic is right (cross-checked against scipy)

"Hand-written statistics" is only a virtue if somebody checked them. Five independent
layers, all executed by `pytest`:

| layer | what it rules out | where |
|---|---|---|
| **scipy agreement, 55 committed cases** | "the formula was remembered wrong" | `tests/fixtures/scipy_reference.json`, generated by `tests/tools/make_scipy_reference.py` with **scipy 1.8.0**, tolerance **1e-9** |
| **exact rational arithmetic** (`fractions.Fraction` + `math.comb`, sharing no code with the float implementation) | "the float code drifts in the tails" | `tests/test_stats_exact.py` |
| **closed forms at the extremes** (`k = 0`, `k = n`) | "the interval is only right around p̂ = 0.5" | `tests/test_stats_intervals.py` |
| **defining equation re-substituted** (the Wilson bounds must satisfy the score equation; the Clopper-Pearson bounds must put exactly α/2 in the tail) | "the interval is a plausible-looking approximation" | same file |
| **Monte-Carlo coverage** for Wilson / Clopper-Pearson / Newcombe | "the interval is anti-conservative or wildly conservative" | same file |

The scipy layer is the one people ask about first. The kit **does not** import scipy —
zero runtime dependencies is a hard rule — so the reference values are generated once on a
machine that has scipy and committed with their provenance. Every CI run, where scipy is
*not* installed, still compares the hand-written code against scipy's answers:

```text
scipy 1.8.0 · python 3.10.12 · 55 cases · max |Δ| < 1e-9
wilson(40, 40)[0]                 0.9123783988027133   mine == scipy
clopper_pearson(40, 40)[0]        0.9119026971211966   mine == scipy
fisher([[1,11],[9,3]])            0.0027594561852201   mine == scipy
binomtest(1, 9, 0.5).pvalue       0.0390625000000000   mine == scipy  (McNemar)
```

Refresh with `python tests/tools/make_scipy_reference.py`: the generator itself refuses to
write the fixture when the two implementations differ by more than `1e-9`, so a refresh can
never bake in a regression. To re-derive everything locally instead of trusting the file:
`pip install scipy pytest && pytest tests/test_against_scipy.py -v`.

Not cross-checkable, because scipy 1.8 has no counterpart — each is verified another way:
`newcombe_diff_ci` by Monte-Carlo coverage, `paired_odds_ratio_interval` by composition
from the Clopper-Pearson values above, and `benjamini_hochberg` against the worked example
in Benjamini & Hochberg (1995).

## End to end: from a rollout log to a conclusion

**1. The input** — one row per `(scene, seed, instruction)` and nothing else:

```json
[{"episode_id": 2400, "seed": 0, "ix": 0, "landed_box": "target_box"},
 {"episode_id": 2400, "seed": 0, "ix": 1, "landed_box": "target_box_b"},
 {"episode_id": 2401, "seed": 0, "ix": 0, "landed_box": null}]
```

`ix` is the index of the instruction in your ordered list (the slot the policy receives).
`landed_box` is `null` when the object never landed anywhere — do not drop those rows, they
are the entire difference between `follow_acc` and ITT. A protocol file says which box each
instruction asks for and where the thresholds are:

```json
{"instructions": ["put it in the left box", "put it in the right box"],
 "expected_box": {"put it in the left box": "box_a", "put it in the right box": "box_b"}}
```

**2. The command** (add `--json out.json --markdown out.md` to keep the artifacts)

```bash
python -m eeval report rows.json --protocol protocol.json
```

**3. What comes out** — the table is the report, the exit code is the gate:

```text
**Verdict: instruction followed** (pass)
| estimand | value | denominator |
| follow_acc | 100.0% | 40 rollouts that landed |
| follow_acc (ITT) | 52.6% | 76 rollouts |
| pairs both followed | 15 / 38 (39.5%) | complete pairs |
| Wilson 95% of follow_acc | 91.2% - 100.0% | - |
| p vs chance (0.50) | < 1e-6 | - |
| side bias p (landing counts {'target_box': 25, 'target_box_b': 15}) | 0.1539 | - |
```

**4. Read it in this order** — each line licenses exactly one sentence:

| line | what you may say | what it does not license |
|---|---|---|
| `follow_acc` + Wilson | "when it placed the object, it placed it where it was told" | "the policy succeeds at the task" |
| `follow_acc` ITT | "the task succeeds X% of the time" | anything about language use |
| `pairs both followed` | "the instruction changes the outcome" | how often the policy chooses to place it at all |
| `side bias p` | "the landing side is not just drifting to one side" | that both sides are equally reliable (check the per-instruction block) |
| `discordant` / McNemar | "one instruction arm fails systematically" | which physical stage fails — that is the judge's job |

**5. When the verdict fails**, the label tells you what broke:

| label | reading |
|---|---|
| `instruction followed` | all three checks pass; quote the numbers and the intervals |
| `landing tracks the instruction, but no pair is fully correct` | the *pairing* is broken: the two arms did not run the same scenes, or one arm is missing |
| `instruction ignored (…)` | landing is indistinguishable from guessing — the policy is not using the input |

**6. Your own task.** If "where did the object end up" is not your success criterion, write
the criterion with `eeval.judge` (gates → one boolean), then feed that boolean in as
`landed_box`. The two halves stay independent on purpose: judging is physics, aggregating is
statistics, and mixing them is how a metric starts measuring itself.

## The protocol

A language-conditioned policy is evaluated by replaying **the same scenes** under **both
instructions**. Outcomes then come in pairs, and three estimands fall out, each with a
defensible denominator:

| estimand | denominator | question |
|---|---|---|
| `follow_acc` (per-protocol) | rollouts that landed in **some** box | when it did put the box down, was it the instructed box? |
| `follow_acc_itt` | **every** rollout | did the whole task succeed? |
| `pairs_both_follow` | complete `(scene, seed)` pairs | did both instructions of the same scene land where told? |

Only the third one is unfakeable: a policy that always drops right scores 100% on half
the rollouts, **0 pairs**. `Report` also publishes the failure breakdowns
(`landed_correct` / `landed_wrong_box` / `never_landed`), the landing distribution with a
bias test, McNemar on the discordant pairs, and the chance baselines a reader would
otherwise have to reconstruct. See [`docs/PROTOCOL.md`](docs/PROTOCOL.md) for the formal
definitions, the worked example, and the six ways this analysis is commonly fudged.

## API in one screen

```python
from eeval import Protocol, Rollout, analyze_rows

protocol = Protocol(
    instructions=("left", "right"),               # order == the policy's language slot
    expected_box={"left": "box_a", "right": "box_b"},
    min_follow_acc=0.80, min_wilson_lower=0.50,   # pre-registered, fixed before the run
    min_pairs_both_follow=1,
)
report = analyze_rows(rows, protocol)   # rows: [{episode_id, seed, ix, landed_box}, ...]

report.follow_acc          # 1.0
report.follow_wilson       # (0.9124, 1.0)   -- the honest version of "100%"
report.follow_acc_itt      # 0.5263
report.pairs_both_follow   # 15
report.verdict.passed      # True
report.to_markdown()       # the table above
report.to_json()           # everything, for a results file
```

|---|---|
| `stats` | `wilson`, `wilson_interval`, `clopper_pearson`, `proportion`, `binom_pmf/cdf/sf`, `binom_two_sided`, `fisher_exact_2x2`, `fisher_test_2x2`, `mcnemar_exact`, `paired_odds_ratio_interval`, `newcombe_diff_ci`, `two_proportion_diff`, `benjamini_hochberg`, `log_binom_coef` |
| `counterfactual` | `Protocol`, `Rollout`, `Report`, `Verdict`, `analyze`, `analyze_rows`, `aggregate`, `aggregate_pairs`, `verdict` |

Every interval function takes `alpha` (default `0.05`); every test returns a plain
`float`; every result object has `as_dict()` and a readable `__str__`.

## Why these tests, not the usual ones

Every choice below is a case where the textbook default gives a wrong or unusable answer on
trial data, with the numbers this project actually hit. All of them are asserted in `tests/`.

| choice here | the usual default | what the default does on this data | why that is not acceptable |
|---|---|---|---|
| **Wilson** interval | Wald (`p̂ ± 1.96·SE`) | 40/40 successes → **`[1.0, 1.0]`, width 0.000** | 40 trials cannot establish certainty; Wilson gives `[0.912, 1.0]` |
| **exact** binomial | normal approximation | at n = 12 the approximation is outside its validity region; a 12/12 run gets p ≈ 0 by construction | exact two-sided p = 0.00049 is both defensible and quotable |
| **Fisher** exact | χ² | the real A/B table `[[1,11],[9,3]]` has a **minimum expected count of 5.0** — exactly on the validity edge; `[[0,12],[8,4]]` breaks it outright | at n = 12 per arm, χ² is a guess dressed as a test |
| **McNemar** exact | unpaired χ²/Fisher | the paired run gives 10 discordant pairs one way, 0 the other (`TF=10, FT=0`, p = 0.00195) | unpaired analysis of the same counts answers a different question and cannot say *which* instruction arm fails |
| **Newcombe** difference interval | Wald difference | perfect separation (12/12 vs 0/12) → Wald **`[1.0, 1.0]`, width 0.000**; Newcombe `[0.657, 1.0]` | the effect is largest exactly when Wald is most confident and most wrong |
| Clopper-Pearson **next to** Wilson | Wilson only | 40/40 → exact `0.9119` vs Wilson `0.9124` | publishing both shows the interval is not an artifact of one convention; CP also guarantees coverage |
| **Benjamini-Hochberg** | "report the smallest p" | a 4-knob × 3-seed ablation is 12 tests | reporting the minimum of 12 p-values is how a null result becomes a finding |

The rule of thumb: **use the exact test when the sample is the size a robot allows.** Exact
methods cost nothing at n ≈ 10² (a few hundred microseconds) and they remove the "your
significance test assumes n = 1000" objection before it is raised.

## What it is not

- **Not a metrics framework.** No plotting, no experiment tracking, no dataset loaders.
  It turns a rollout log into a defensible number and gets out of the way.
- **Not for huge samples.** Exact tests are `O(n)` per call; fine for hundreds of
  rollouts, silly for a million. Use a normal approximation at that scale and say so.
- **Not a substitute for replicates.** A single seed, a single scene set, and n = 12
  trials stay single-sample statements no matter how exact the arithmetic is. The kit
  makes the uncertainty visible; it cannot manufacture evidence.
- **Not free of assumptions.** Independence between scenes, a fixed instruction set, and
  a judge that actually measures what it claims. Everything the protocol assumes is
  written down in [`docs/PROTOCOL.md`](docs/PROTOCOL.md).
